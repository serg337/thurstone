# Architecture

Thurstone separates authoring, execution, and results into three top-level documents so expected answers and repair hints do not share the active Lab trust surface.

```text
/studio   draft, human review, freeze, phase-specific meta-tools
/lab      deterministic sandbox and state-appropriate target tools only
/results  post-unlock sealed evidence, inspector, exports, repair controls
```

## Shared deterministic domain

The checkout fixture and domain functions are strict TypeScript modules behind one serialized session store. Normal UI controls and native WebMCP handlers call that same store. `cart_get` returns only line-item identity and quantity; the non-overlapping `order_review` tool owns prices, totals, shipping, and delivery framing.

Every mutation requires a bounded operation ID. The same ID and canonical command replay the original terminal receipt without another effect; conflicting reuse fails. Document-lifetime tombstones survive fixture reset so a late retry cannot mutate a fresh fixture. Checkout can only enter or leave a simulated pending-human-approval state.

## Native WebMCP

The Lab feature-detects provider registration separately from in-page discovery and execution. A central per-tool registry manager owns registration promises and `AbortController` lifecycles. It preserves unchanged tool identities, blocks new admission while transitioning, drains in-flight handlers, and verifies the exact discovered catalog. Direct native calls also hold the selected registration through outer consumer result delivery: Chrome 152 can still be settling `executeTool()` after the provider handler resolves, so a state-driven self-retirement must not abort that registration signal early. The transition reports `registering` and freezes admission immediately, then publishes only the exact state-appropriate catalog after the consumer hold releases. The document-scoped Lab environment preserves handler identities across same-document route remounts.

The official ambient type package currently lacks `executeTool()`, while the draft and Chrome guide differ on object versus JSON-string arguments. Thurstone keeps this difference behind one narrow adapter. It detects one mode with exactly one harmless read-only `cart_get` call, freezes that mode for the document, owns a data-only snapshot of every later input, consumes each execution ID before asynchronous work, and never retries with another representation.

Chrome 151's `getTools()` descriptor serializes `inputSchema`. Discovery parses that representation once and then requires the schema content, title, description, and annotations to match the provider declaration exactly.

Readiness keeps the active tool-registry hash separate from the fixture state hash. The registry hash covers the state-appropriate metadata, annotations, handler/domain/toolset versions, and application commit; ordinary quantity changes therefore do not masquerade as registry changes. Each direct native adapter receipt binds raw/canonical result, trace ID, before/after state, effect digest, and the registry used at dispatch.

A document-owned Gate 1 proof journal records explicit Registry statuses, sanitized Readiness receipts, native attempt starts/finishes, reset outcomes, and one-button sequence timings across same-document route remounts. The one-button path writes only a bounded build/path/expiry-bound request to session storage, reloads once, consumes that marker before any await or native call, and claims one document-owned runner. Every step uses the real adapter and condition-driven readiness waits; any mismatch stops without a verified download. Export seals the journal into a SHA-256 chain and combines it with the full trace ledger, state inspection, archives, current receipts, commit, origin, and runtime identity in one local JSON download. It never serializes storage, live `Window`, ModelContext, handler, signal, store, or controller objects. Ordinary full reload still starts a new proof document and never replays a consumed request.

## Reset and trace boundary

Reset temporarily closes session admission, drains prior work through the serialized store, archives the old trajectory, restores exact fixture bytes, reconciles the initial catalog, and verifies both session summaries and full canonical trace-ledger evidence before releasing admission. An invalid or interrupted verification cannot start a trial.

Raw input is captured at public method entry before queueing or validation. Descriptor-safe normalization does not invoke ordinary getters and retains otherwise non-JSON structure as tagged evidence. Canonical arguments remain separate. Cancellation is latched through asynchronous trace finalization; post-result cancellation and post-state-commit cancellation are recorded separately. Chrome can reject the consumer-side `executeTool()` promise after a harmless handler has naturally completed, so adapter cancellation and handler status remain separate facts: the verifier accepts a reached completed `cart_get` only with exact empty arguments/result, null handler error, no commit, identical state, and a complete no-effect binding.

## Probe and evaluator boundary

The preferred Probe is a bounded server-assisted model decision plus in-page native execution. The model receives one natural-language request, minimum fixture synopsis, live state-appropriate catalog, and a frozen generic instruction. It receives no expectations, family/subset labels, prior result, or repair hint.

Evaluator truth remains outside the Lab and model request. A server-issued signed single-use envelope binds opaque run/case/trial, session, build, fixture, request, settings, and manifest hashes. Runner-owned transport IDs are deterministically derived from that opaque signed trial identity and prebound into every applicable mutation schema. A stable Redis namespace enforces a versioned 160-attempt/USD $10 lifetime policy across deployments and provider resets. Each granted call permanently consumes one slot and $0.0625 of admission capacity; uncertain outcomes quarantine rather than refund.

Gate 2 used one preferred custom Probe implementation. Attempt 1 remains a complete authentic 0/4 semantic failure; attempt 2 remains a terminal-invalid one-call infrastructure lineage without a reconstructed row; attempt 3 is a complete sealed authentic 0/4 semantic failure. The first pinned fallback attempt remains separate authentic 3/4 evidence. A sealed artifact proves evidence retention and integrity, not Gate 2 acceptance. The migration chain preserves every call, cost, and receipt from v0.2 onward. Operator exchange is actor-bound and fixed-expiry; only its valid HttpOnly credential can create the activation-wide run anchor. Session issuance writes a bounded encrypted run index before returning a short-lived HttpOnly session, a longer fixed-expiry HttpOnly recovery credential, a CSRF token, and an opaque encrypted continuation. Every trial reloads into a minimal `/lab` document, claims one bounded document owner for the current index revision, verifies/resets the fixture, discovers the live catalog, obtains one server-allowlisted request, makes one stateless Responses call, re-verifies the catalog, and permits zero or one native dispatch.

The provider authorization remains in flight until the client captures the canonical handler trace and completes another verified reset. Server-only evaluation then seals the terminal row and settles known usage. Encrypted Redis recovery records make issue, decision, native admission, and completion delivery idempotent without retrying inference or native execution. The monotonic run index advances after each sealed row and can reissue only the same actor/build/activation/run binding until its original fixed expiry; it never stores prior semantic evidence in plaintext or exposes it to Lab. Terminal evidence is revealed on `/results`, never in the active Lab. After human approval, the local runner recovers a fresh short session and exact document ownership from the fixed recovery credential before acknowledgement and encrypted-data deletion.

The preferred path is exhausted, and the first fallback attempt's 3/4 result remains a failure. Its reset defect was reproduced and repaired without inference; the final exact v0.5 attempt then completed separately at authentic 4/4 and was acknowledged. Gate 2 is complete, the calibration allocation is terminal, and no v0.6 exists.

The fallback adapts only the pinned upstream `Page.webmcp.tools()` and retained `WebMCPTool.execute()` pattern; it does not import the upstream expected-call evaluator or shared-browser report. Each trial launches the exact hashed Chrome 151 binary in a new process/profile, admits one top-level same-origin catalog, terminates on foreign requests or additional targets, sends the live manifest as strict Responses function tools, and consumes the server-side native allowance before the retained handle executes. A same-origin adapter carries only signed opaque authorization/recovery state across fresh processes. Full provider bytes, native events/result, canonical handler trace, state/effect, reset lineages, costs, and deterministic evaluation are independently reverified before terminal reveal. Runner v1.1 binds its implementation components as well as prompt/settings; the verifier retains a frozen v1 path for prior evidence.

The v0.5 transition and final run preserve all historical calls, heterogeneous policy identities, costs, receipt chain, prior fallback evidence, zero-provider reproducer, ACK anchor, and the permanent expired pre-dispatch tombstone. The active allocation is `17/70/2/70/1` under the original 160-call/USD $10 caps.

The last allocation is exposed only through the signed-out source-fixed judge lane. The public request cannot carry a prompt, tool, schema, model, URL, settings, or operation arguments. Server activation binds the exact Vercel project/commit, existing guard identity, fixed clean fixture, live initial manifest, generic runner, and model settings. Before common-ledger issuance, a permanent AES-GCM singleton anchor freezes exactly one signed `judge` claims set and its actor/subject hashes; concurrent callers recover that winner instead of creating more permanent authorization keys. Atomic `BEGIN` advances the same lifetime ledger from the settled 91-call boundary and records its bounded in-flight lease. After a known response, the full request/response/usage receipt is AES-GCM sealed in a distinct non-TTL namespace before known settlement. A lost response recovers that receipt without inference; an expired in-flight lease settles conservatively uncertain and can never redispatch.

The public archive contains only a canonical sanitized projection and its digest. The sole provider decision was sealed on evidence root `e2cf8d47375abfeeb4f32bd6f5973918acf4c091`; it selected `cart_get` with `{}`. Upstash's automatic JSON deserialization exposed a string-only assumption in the archive reader after the encrypted permanent capture had completed. Recovery accepts the already parsed projection as well as its wire string, then applies the same strict schema and digest checks. It does not rewrite the permanent record, alter the guard or cost, or dispatch the provider again.

The current Lab must independently reach a clean, halt-free `consumer-ready` catalog before it can execute the returned `cart_get` with `{}` through the native adapter. Provider and native evidence are intentionally separate: an archive-presentation successor cannot inherit native proof from the evidence root and must retain a fresh replay from its own deployed build. The recovery lineage binds the immutable root provider projection to that presentation repair with zero provider calls. If needed, Gate 9 can extend the lineage by one optional link-only release hop; every transition must remain contiguous and preserve the fixture, tool catalog, judge runner, dependencies, provider receipt, guard, and cost.

Gate 3 freezes the exact 24-case suite, target, runner, evaluator, order, and retry rules before scored work. The first complete baseline and isolated Repair are acknowledged permanent evidence. A disabled v2 deployment later found that stored freeze reads were incorrectly coupled to current metadata; no revised call occurred. The repaired successor protocol therefore reruns both v1 and v2. Its v1.1 freeze binds the original review/freeze/run/Repair records, offsets `24/1/0`, unchanged semantic target/runner/evaluator projections, and the original Authoring termination. Legacy artifacts stay in their original hash domains, while successor/frozen Studio becomes read-only and exposes no authoring meta-tools.

## Evidence

Raw model bytes, parsed decision, raw/canonical arguments, native result, before/after state bytes, effect diff, runtime identity, and deterministic score remain separate layers joined by canonical hashes and terminal receipts. The Gate 1 bundle is explicitly native-plumbing evidence, never model-selection, semantic-scoring, or Direct ChatGPT evidence. Hashes establish internal consistency; they are not independent attestation.

The Results page, browser JSON, browser Markdown, and server export routes are built from one trace-derived 48-record projection. Seven metrics retain their own exact numerators/denominators, Development and blinded holdout remain separately filterable, and every record exposes request, catalog, decision, arguments, result, state/effect, score, hashes, runtime, and provider projections. Custom Probe, Direct Site Tools, calibration, native plumbing, and judge evidence remain separate namespaces; the one-call judge projection and two-to-four Direct observations never alter the 24-case denominator.
